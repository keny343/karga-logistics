# Database

PostgreSQL 17. Plain SQL migrations, no ORM: the queries in this system are
mostly reporting and filtered lists, which are clearer written out than assembled
by a query builder.

## Migrations

Files in `backend/migrations/`, named `NNN_description.sql`, applied in order.

```bash
npm run migrate
```

Each file runs once inside a transaction, and its checksum is recorded in
`schema_migrations`. Editing a file that was already applied is **refused**, not
ignored: the file and the database would silently disagree, and the difference
would only surface somewhere expensive. Fixing an applied migration means writing
a new one.

## Conventions

**Identifiers.** `uuid` primary keys generated by `gen_random_uuid()` from
`pgcrypto`. Orders additionally carry a human code (`KRG-000001`) because that is
what people read over the phone. `audit_logs` uses `bigserial`: it is append-only
and never referenced by an API path.

**Time.** Every timestamp is `timestamptz`. The database stores UTC; formatting to
Angolan local time happens at the edge.

**Money and weight.** Integers only — value in cêntimos, weight in grams. A float
that represents money eventually loses a cêntimo, and the loss is only found when
a total disagrees.

**Coordinates.** `numeric(9,6)` for latitude and longitude, in their own columns.
PostGIS is the eventual home, but nothing yet performs a real spatial query, and an
unused extension is a dependency that breaks builds for nothing. Distance
comparisons in phase 5 use a bounding box plus haversine, which is exact enough for
"which drivers are near this pickup" in a city.

**Deletion.** Business rows are deactivated, not deleted: `is_active`. History that
refers to a person survives that person's account, so `audit_logs.actor_id` is
nullable with `ON DELETE SET NULL` and carries a text label copied at write time.

## Tables today (phase 1)

| Table | Purpose |
|-------|---------|
| `companies` | The tenant. Everything else hangs off it. |
| `users` | Accounts with a role, unique per company by email. |
| `audit_logs` | Append-only record of sensitive actions. |
| `schema_migrations` | Which migrations ran, and their checksums. |

`user_role` is an enum (`ADMIN`, `OPERADOR`, `MOTORISTA`, `CLIENTE`). Four values
the code branches on belong in the type system rather than in a table someone can
edit into a state the code cannot handle.

Email is unique **per company**, not globally: the same person may drive for two
carriers, and one carrier must not be able to learn who exists at another.

## Indexing

Indexes are added for queries that exist, not for columns that look important.
Today: `users (company_id, role) WHERE is_active` for the member lists,
`audit_logs (company_id, created_at DESC)` for the audit feed, and
`audit_logs (resource_type, resource_id)` for "what happened to this order".

Later phases add composite indexes keyed on `company_id` first, because every
business query filters on it before anything else.

## Integrity

Foreign keys everywhere, with the delete behaviour chosen per relationship:
`RESTRICT` where losing the parent would orphan operational data, `SET NULL` where
history must outlive it. Check constraints where a value has a shape — a company
slug, an email containing `@`. The database refuses an impossible row even if a
bug in the API asks for one.
